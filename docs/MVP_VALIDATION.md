# MVP and Delivery 1 validation audit

Audit scope: `MVP_plan.md` section 8, Delivery 1 cases D1-01–D1-20, and v0.4 security cases SEC-01–SEC-07. This is an evidence audit of the current code and tests, not a claim that the native macOS application has passed manual acceptance.

**Status key:** `PASS automated` means the behavior is covered by a passing automated test (or an explicit static configuration test); it does not imply an unrun native/manual check. `PARTIAL` means some behavior is covered, but the complete acceptance case is not established. `NOT VERIFIED` means no relevant acceptance-level evidence was found or the required runtime measurement was not performed.

## Explicitly unverified, deferred, and known gaps

- **Native WebView PTY:** real `yes` for 30 seconds, `nvim` interaction, redraw after resize, byte-loss/latency, UI responsiveness, and idle CPU (including five sessions) were **not verified**. The production path exists, and unit tests cover byte/chunk handling and IPC dimensions, but these do not establish the spike/acceptance guarantees.
- **Font:** `TerminalSession.vue` configures `FiraCode Nerd Font Mono`, 16 px, `lineHeight: 1.2`; `TerminalSession.test.ts` asserts those options. **Ligatures ON remains unmet:** no implemented ligature renderer/addon or visual WebView test establishes it. Installed `@xterm/xterm` is 6.0.0; it has no Terminal font-feature/ligature option, and this repo has neither `@xterm/addon-ligatures` nor `@xterm/addon-webgl`. Its `registerCharacterJoiner` API is documented as WebGL-only, so it is not a supported route with the shipped renderer. The package's DOM row factory does consume joined ranges, but that source/API mismatch is not a verified WebKit integration. A CSS flag alone is not evidence that terminal glyph shaping works. The exact `FiraCode Nerd Font Mono` family is installed on this Mac (`~/Library/Fonts/FiraCodeNerdFontMono-Regular.ttf`); rendering and ligature shaping in the native Tauri WebView are not verified.
- **Editors and signing:** argument construction and editor availability logic have tests, but actual Zed/Neovim launch from the packaged native app was not checked. macOS signing/notarization was not verified. `tauri.conf.json` declares hardened runtime and a DMG target; that configuration is not proof of a signed artifact.
- **Deferred session kinds:** `server` and `custom` session launch are not available in the WebView; current UI says to use Shell for commands. v0.4 includes both in Delivery 1, so this remains a delivery gap.
- **Known bundle warning:** `pnpm build` succeeds but Vite warns about chunks over 500 kB. The built `ChangesPane` chunk is **1,083.81 kB** (331.39 kB gzip); `markdown-preview` is 298.01 kB and the main JS chunk is 474.00 kB. No bundle optimization was attempted in this audit.
- **Q1 worktree location:** configurable external storage is the working interpretation of the user's approval to continue. Confirm the precise default before acceptance/release if needed.

## Actionable native/manual acceptance checks

1. Confirm the provisional Q1 location choice before release if needed. In the native app, create a worktree from the palette, confirm it starts from the chosen default branch, opens/focuses, and launches its shell in that checkout; test a branch already held elsewhere.
2. On macOS, run `yes` for 30 seconds through the WebView PTY; verify UI responsiveness and output integrity. Run Neovim, resize repeatedly, verify redraw/input/alternate screen, then leave five sessions idle and measure CPU. Record machine/build, duration, observed loss/latency, and CPU rather than reporting a visual impression as a measurement. Also run `printf '!= !== == === => -> <- <= >= && || ::\n'` in the native Tauri WebView terminal and visually verify Fira Code ligature glyphs (not just CSS or a separate browser page); record the WebView/macOS version and screenshot. If absent, use a renderer/addon with explicit WebKit support or first validate a minimal character-joiner path against xterm's DOM renderer in that WebView; do not mark ligatures enabled based on configuration alone.
3. Edit a tracked file from a terminal and confirm Git status, Changes, and file tree refresh without a manual refresh (D1-09). Delete a worktree directory outside Marvis and verify Missing plus Locate/Close (D1-14). Run terminal and editor activity concurrently and verify the signal (D1-16).
4. Quit/relaunch the native app and verify repos, checkout order/focus, layout/splits, and historical sessions (inactive PTYs) restore correctly (D1-17). Exercise the no-remote/no-`main` branch-choice prompt and verify the saved choice is reused without prompting again (D1-19).
5. Open a 4,000+ line diff in the native app; verify interaction remains responsive and rendered rows stay bounded (D1-11). Automated paging/row-window tests are not a substitute for the UI responsiveness check.
6. With Zed and Neovim installed, open a selected file at an exact line from the running app; repeat from the packaged build. Verify the macOS artifact's signing state separately; no signing result is established by `hardenedRuntime: true`.
7. Decide whether `server`/`custom` are intentionally deferred despite v0.4's Delivery 1 scope, or implement them in the proper feature work; do not mark Delivery 1 complete while the mismatch remains unresolved.
8. Close the SEC-01/SEC-06 contract gaps before declaring the security suite complete: decide whether SEC-01 explicitly accepts rejection instead of canonicalizing a `..` path, and extend SEC-06 negative tests to cover repo/checkout/session ownership for each relevant command family. Keep these tests named `sec_` so `pnpm test:security` continues to exercise them in CI. No test was added in this audit: the remaining evidence gaps require a clarified contract, broader command-ownership coverage, or native integration/stress runs rather than a small isolated test that would overstate the behavior.
